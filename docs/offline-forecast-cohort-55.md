# Offline series cohort replay (#55)

`replayOfflineSeriesCohort` is a synthetic regression harness for S11-A selection. Existing immutable receipts deliberately contain `evaluationEligible: false`. A successful replay preserves that flag and reports published calibration as unsupported; local receipt timestamps do not prove that viewers saw a forecast. No production receipt format, collector, UI or metric is changed.

Policy `latest-compatible-prestart-series-v1` selects the latest receipt for the exact match/event, ordered source participants, best-of, model version and config hash, published strictly before both its scheduled start and the supplied observed actual start. Ties use forecast revision then receipt key for deterministic selection. This is a series target, including Bo1 as a series; individual games and tournament advancement are separate future targets. Each match contributes one binary home-oriented row, regardless of receipt revisions or duplicate outcome rows.

Complete outcomes require a legal terminal Bo1/3/5 score and ordered observation/completion/start timestamps. Outcomes observed after the as-of cutoff, cancellations, unresolved or contradictory results, incompatible model versions, changed participants and missing pre-start receipts yield named exclusions. Identical repeated observations are counted once; conflicting observations with the same match ID are withheld without selecting whichever arrived last. No outcome is inferred from a forecast.

Tests cover latest-revision selection, immutable/reordered inputs, duplicate/conflicting outcomes, an actual early start, format/result validation, model separation and unavailable publication evidence. The numerical fixture harness below adds offline metric references and baseline pairing. Confidence intervals, real outcome provenance, production cohort certification and the diagnostics UI remain open under #55.

Observation cutoff filtering precedes deduplication and conflict detection. Later corrections cannot rewrite an earlier cohort. `afterCutoffOutcomeRows` counts withheld future rows, including corrections for already selected matches; future-only matches receive the `outcome-after-cutoff` exclusion. Regressions include a mixed visible/future correction in both orders, Bo1/Bo3 series targets and same-time revision selection.

Owner gate: supply auditable public-delivery evidence for immutable pre-start receipts and confirmed licensed outcomes before claiming published forecast calibration. Preserve data source, model/config, receipt key, actual start, outcome observation and cutoff artifacts. Rights and representative observations remain activation gates. ## Metric and paired-baseline fixtures

`summarizeOfflineForecastMetrics` consumes the synthetic series replay only. It preserves the replay policy, model/config, evidence reference, receipt keys, exclusions and unsupported published-calibration result. It reports series and event counts; event-aware uncertainty remains explicitly unsupported. No production certification, collector or UI is activated.

The shared `binary-brier-clipped-log-loss-v1` contract uses `(p - outcome)^2` and natural-log loss with the observed-outcome probability clipped to `[0.001, 0.999]`, matching `predictionModel.ts`. The extraction leaves existing walk-forward rounding and results unchanged. Offline fixture averages retain full precision. Exact wrong zero/one forecasts have Brier 1 and log loss `-ln(0.001)`; correct endpoints have Brier 0 and log loss `-ln(0.999)`. `impossibleOutcomeCount` exposes catastrophic endpoint errors despite the existing clipping rule. This is not the separate paired-export script's `1e-12` clipping contract.

Reliability bins extend the existing game/favorite-oriented definition explicitly: these fixtures use one home-oriented probability per series, in ten intervals `[0, 0.1)` through `[0.9, 1]`. They never count both sides. Empty bins and empty metric/comparison denominators report null means/losses/deltas, not zero performance. No bin intervals or calibration claims are produced.

The coin-flip baseline reuses the existing 0.5 definition. Other baselines must be explicit synthetic series-probability fixtures with a model/config and evidence reference; game probabilities, team-only ratings and pregame win rates are not inferred from receipts or outcomes. Fixture rows pair by the exact selected receipt key, and their information must be available at or before that forecast's publication time. Missing, conflicting, invalid and late rows are named exclusions. Identical duplicates pair once; unmatched baseline rows are counted. Each comparison recomputes both forecast and baseline on the identical paired subset, exposes its receipt keys and count, and reports baseline loss minus forecast loss (positive favors the forecast). Baseline keys must be unique; incompatible fixture definitions cannot be silently pooled.

`tests/offlineForecastMetrics.test.ts` provides hand-computable bin, Brier, log-loss and paired-denominator references, including empty/tiny samples, all-correct/all-wrong endpoints, missing/duplicate/conflicting baselines and information-cutoff failures. Shared synthetic receipt fixtures also exercise the real replay selector. Production baselines, uncertainty and the public diagnostics pipeline remain subsequent slices.
