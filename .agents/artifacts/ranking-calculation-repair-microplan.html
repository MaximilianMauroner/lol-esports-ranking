Ranking calculation repair Microplan

Project: LoL Esports Power Index · Scope: model correctness, league fairness, tournament scoring, and source freshness

Recommendation

Ship these repairs as one versioned model revision followed by a full historical replay. The four calculation changes interact through team ratings, league anchors, tournament placement, uncertainty, and later match expectations. Publishing only one fix at a time would create intermediate rankings that are hard to explain or compare.

Target release: transparent-power-index-v0.1.0, with a new config hash and fresh source manifest. Keep the public schema version unchanged unless implementation adds or renames serialized fields.

Goal

Make rating movement invariant to unrelated scheduling, make tournament scoring independent of event labels, enforce the stated result-signal budget, center placement adjustments, and prevent stale or contradictory source state from reaching published artifacts.

Scope

Included

  • Recency and boundary decay calculations.
  • International team and league signal allocation.
  • Tournament phase and placement residual calculations.
  • Schedule-result reconciliation and lifecycle completion.
  • Raw manifest freshness checks.
  • Full replay, calibration comparison, and regenerated public artifacts.

Not included

  • UI redesign or ranking-table changes.
  • Changing the rated league universe.
  • Replacing Oracle's Elixir or Leaguepedia.
  • New player metrics or execution-residual promotion.
  • Production cadence or bucket-retention changes.

Decisions

Decision 1

Use entity-local context and composable time decay

Replace the floor-plus-exponential gap function with anchor regression based on an exponential rate. Track the last rated date, normalized split, and patch per team. Track elapsed time and split context per league anchor. Apply each boundary when that team or league next participates, never by comparison with the globally previous match.

Reason: inserting matches from another team or league must not trigger, suppress, or split any decay or boundary adjustment.

Decision 2

Use phase data for stage points

Normalize match.phase into explicit stages. Cover provider labels such as upper final, lower final, lower round, Swiss, knockout stage, quarterfinal, semifinal, and grand final. Do not search the event title for stage tokens. Skip placement scoring when recognized-phase coverage is below 90% of tournament series or the terminal final is not recognized and resolved.

Reason: changing an event label must not change rating movement.

Decision 3

Separate base evidence from realized movement

Calculate one signed baseEvidence value per side, allocate 12% to league strength, then divide the remaining 88% between stable team strength and form. Exact configured shares apply to these base allocations. Team uncertainty, roster volatility, domestic transfer shrinkage, momentum decay, caps, and rounding produce separate realizedDelta values. Remove the independent league K-factor from the live calculation.

Reason: configured shares can reconcile exactly at the evidence layer while realized team movement remains honest about entity-specific modifiers.

Decision 4

Center placement movement

Scale expected stage points to the actual tournament point pool before computing residuals. After league aggregation, center and cap deltas with redistribution so the final league placement adjustments sum to zero within rounding tolerance.

Reason: tournament placement should redistribute league strength, not create rating points.

Decision 5

Reconcile completed series with schedule state

Keep provider schedule state as reference data, but derive effective completion at series level. Scored data corroborates completion only when the canonical series reaches the official wins-needed threshold, or completes a valid best-of-two tie. One scored game sharing an officialMatchId is insufficient. An official completed state is accepted only when scored coverage does not contradict its final score.

Reason: a stale unstarted flag must not override a completed series, and a partial Bo5 must not be promoted to complete.

Decision 6

Fail publication on semantic manifest drift

Parse managed raw inputs and compare scored coverage, retrieval timestamps, content digests, and manifest references. Do not use filesystem modification time. A refresh may preserve a verified prior authority during provider outage, but it must not silently ignore a successfully downloaded scored file with new coverage or content.

Reason: the repository already contains files through July 26 while the manifest ends July 16.

Ordered implementation

1. Lock the defects with invariant tests

  • Add a recency test that compares one 180-day gap with the same gap split by unrelated match dates.
  • Add unrelated-match insertion tests around team patch changes, team split changes, and league-anchor split changes.
  • Add an event-label test using identical phase, tier, teams, and result with Worlds and World Championship titles.
  • Add a channel-budget test that reconciles baseEvidence allocations against declared shares, then separately verifies realized-delta modifiers.
  • Add a placement test asserting that final league placement deltas sum to zero.
  • Add source tests for partial Bo5 coverage, completed sweeps, best-of-two ties, stale schedule states, and semantically unreferenced raw files.

Files: tests/model.test.ts, new focused tests for rating context, placement residuals, and manifest freshness.

2. Replace recency decay

  • Add a named half-life or decay-rate parameter to modelConfig.ts.
  • Change time retention to exp(-rate × elapsedDays).
  • Add checkpointed maps for team last-rated date, patch, and normalized split, plus league last-rated date and normalized split.
  • Apply team decay and boundaries before that team's first series on a date. Apply league decay and boundaries before reading that league anchor.
  • Use sourced normalized split identity. If split identity is unknown, apply time decay only rather than comparing event-title strings.
  • Keep team ratings and league anchors symmetric around their own priors.
  • Invalidate old checkpoints through the model config and checkpoint compatibility identity.

Files: src/lib/ratingContext.ts, src/lib/modelConfig.ts, checkpoint tests.

3. Repair tournament stage and placement math

  • Inventory phase labels across the complete source corpus before defining the mapping.
  • Extract a tested phase normalizer for final, upper and lower finals, semifinal, quarterfinal, knockout rounds, Swiss, main-stage, play-in, and unknown.
  • Make stage points consume the normalized phase only.
  • Require at least 90% recognized series-phase coverage and a recognized resolved final. Otherwise skip placement scoring and publish an audit reason.
  • Scale expected team points so expected total equals actual total.
  • Aggregate by home league, apply representative normalization, then center and cap without changing the zero-sum total.
  • Record actual pool, expected pool, and centered residual total in full audit output.

Files: src/lib/placementResiduals.ts, tournament tests, audit snapshot types if diagnostics are serialized.

4. Unify the international result budget

  • Compute baseEvidenceA = eventK × strengthSignal × (observedA - expectedA) and baseEvidenceB = -baseEvidenceA.
  • Allocate baseLeague = baseEvidence × 0.12, baseStable = baseEvidence × 0.88 × 0.90, and baseForm = baseEvidence × 0.88 × 0.10.
  • Apply league base allocations symmetrically so league movement remains zero-sum.
  • Calculate realized stable movement after uncertainty, roster volatility, and domestic transfer multipliers.
  • Calculate realized form movement after momentum decay and caps.
  • Remove or retire live leagueKFactor parameters and update explanations.
  • Publish base allocations, realized deltas, and modifier values in the full audit ledger. Exact share reconciliation applies only to base allocations.

Files: src/lib/ratingSeriesEngine.ts, src/lib/leagueRatings.ts, src/data/rankingConfig.ts, src/lib/modelConfig.ts, explanation tests.

5. Fix source and lifecycle reconciliation

  • Store schedule state as provider evidence rather than unquestioned match state.
  • Group enriched scored games by canonical series and official match identity.
  • Corroborate completion only when official best-of and scored wins resolve a terminal result. Accept a best-of-two tie only at 1-1.
  • Reject one-game and otherwise partial multi-game coverage as completion evidence.
  • Keep tournament completion strict about schedule coverage and rated-match coverage.
  • Add a manifest inventory check based on parsed scored date range, provider retrieval time, content digest, and referenced authority.
  • Regenerate the manifest from the complete verified raw authority.

Files: src/lib/importers/communitySources.ts, src/lib/internationalTournaments.ts, refresh scripts, source authority tests.

6. Recalibrate and compare

  • Run a full historical replay under the old and new model using the same source authority.
  • Run paired chronological walk-forward comparisons on the same predictions, with series-clustered bootstrap intervals for Brier score and log loss.
  • Require global non-inferiority with a predeclared margin of 0.0005 Brier and 0.001 log loss at the 95% upper confidence bound.
  • Require the cross-region Brier point estimate to improve and its 95% upper bound to remain at or below the global non-inferiority margin.
  • Report cross-region Brier, calibration slope, and expected calibration error by home league when the slice has at least 50 predictions. No reported league may breach a 0.001 Brier non-inferiority margin.
  • Compare patch transitions, roster changes, and tournament slices with the same paired method.
  • Run the Riot GPR comparison and inspect large rank changes manually.
  • Review league anchor movement, especially LCK, LPL, LEC, LCS, LCP, and CBLOL.
  • Adjust only named parameters. Do not add one-off team or league corrections.

Output: a checked-in model/config change and local before-and-after audit evidence tied to source digest and model versions.

7. Publish one coherent generation

  • Bump the model version to transparent-power-index-v0.1.0.
  • Generate a new config hash and rebuild every scope, history, entity, region, tournament, and match artifact.
  • Run the full release check before promotion.
  • Publish only when the manifest coverage date matches the latest verified scored input.
  • Keep the prior complete generation as the rollback target.

Risks and controls

Large ranking movement

League anchors and international teams may move sharply because current international results affect both team and league channels more than the metadata claims.

Control: publish old-versus-new rank, rating, and component diffs before promotion.

Under-reactive league ratings

Making the 12% share literal may slow league learning.

Control: tune the declared share through walk-forward and cross-region results, not through a second hidden K-factor.

Sparse tournament metadata

Some providers use vague phase names.

Control: inventory real provider labels, publish recognized coverage, and skip placement scoring when the 90% coverage and resolved-final gate fails.

Historical incompatibility

Existing histories and checkpoints describe the old calculation.

Control: force a full replay, reject old checkpoints for the new config hash, and preserve the old generation for rollback.

Done criteria

  • All six audit findings have regression tests.
  • The four calculation invariants pass on fixtures and the full audit artifact.
  • Team and league boundary state is entity-local and checkpointed.
  • The model metadata and audit ledger distinguish base evidence from realized movement.
  • No partial official series can satisfy tournament completion.
  • Placement scoring fails closed when phase coverage is insufficient.
  • The raw manifest includes every verified scored input selected for publication using semantic coverage and digest checks.
  • The new model passes prediction, Riot GPR, incremental, and release gates.
  • Every public ranking artifact carries the new model version, config hash, source authority, and coverage window.
  • The prior complete generation remains available for rollback.
