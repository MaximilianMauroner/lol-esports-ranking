Roster, substitute, reliability, and accuracy Microplan

This plan replaces inferred "current" roster claims with dated evidence, connects substitute participation to scoring, prevents postgame lineup knowledge from entering pregame evaluation, and makes data quality visible on the site.

Primary goalMore accurate roster-aware ratings
Secondary goalHonest lineup and freshness language
Release policyShadow first, gated promotion
Expected shapeFive implementation phases
Recommendation. Implement the evidence model and evaluation gates before adding lineup simulation controls. A polished "what if" control built on unreliable starter labels would make the problem harder to spot.

Goal

Represent what is known about a team's lineup at a specific time, distinguish short substitutions from lasting roster changes, and price lineup uncertainty without discarding useful partial evidence.

Scope

Included

  • Canonical series-level lineup observations.
  • Starter, substitute, role-swap, and roster-era classification.
  • Evidence timestamps and pregame knowledge checks.
  • Coverage-weighted player priors for partial lineups.
  • Roster-sensitive uncertainty and calibration slices.
  • Lineup history, freshness, and source display in the team UI.
  • Build-time source disagreement and data-health checks.

Not included

  • Manual editorial roster maintenance as the primary source.
  • Rumor ingestion or unsourced injury reports.
  • A public prediction market or user-submitted roster database.
  • Changing the published ranking solely because the UI changes.
  • Calling inferred appearances an officially confirmed roster.

Decisions

  1. Observed is not confirmed. A scored game proves who played that game. It does not prove the next lineup.
  2. Knowledge has time. Every lineup claim records when the system could know it, not only when the match occurred.
  3. Series are the roster update unit. Do not collapse two same-day series into one roster event.
  4. Partial evidence shrinks; it does not disappear. Missing roles use league-role priors and widen uncertainty.
  5. Temporary substitutes do not erase team history. They reduce coordination confidence and add a player-quality adjustment for the affected role.
  6. Permanent changes open roster eras. Use repeated series, split participation share, or explicit sourced permanence.
  7. No public model promotion without paired evidence. Global, cross-region, and roster-change gates all apply.

Target data model

type LineupEvidence = {
  team: string
  seriesId: string
  effectiveAt: string
  knownAt: string
  sourceProvider: string
  sourceUrl?: string
  basis: 'official-announcement' | 'official-schedule' | 'scored-series'
  roles: Partial<Record<Role, LineupPlayerEvidence>>
}

type LineupPlayerEvidence = {
  playerId: string
  role: Role
  status: 'starter' | 'substitute' | 'role-swap'
  confidence: number
}

type TeamLineupState = {
  lastObserved?: LineupEvidence
  latestComplete?: LineupEvidence
  latestPregameKnown?: LineupEvidence
  rosterEraId?: string
  expectedRoles: Partial<Record<Role, ExpectedRolePlayers>>
  coverage: number
  freshnessDays: number
}

The persisted checkpoint must include the current roster-era identity, latest usable evidence per team, and substitute counters needed for incremental parity.

Calculation policy

Partial lineup adjustment

observedEdge = sum(roleWeight × knownPlayerEdge)
missingPrior = sum(roleWeight × leagueRolePrior for missing roles)
rawLineupEdge = observedEdge + missingPrior
effectiveLineupEdge = rawLineupEdge × sourcedCoverage × freshnessWeight

Coverage and freshness also contribute to prediction uncertainty. Keep the player prior and coordination retention as separate ledger channels.

Temporary substitute

teamStableRetention = prior roster-era retention
coordinationPenalty = roleWeight × temporarySubPenalty × evidenceConfidence
playerQualityDelta = substitutePlayerPrior - expectedStarterPrior
uncertaintyIncrease = substitutionAmbiguity + thinPlayerSamplePenalty

Do not open a new era until the substitute reaches the configured series count, split share, or permanent-source threshold.

Unknown future lineup

Use an expected role mixture when recent rotation supplies enough evidence. Otherwise use the last pregame-known complete lineup, shrink it by age, and widen the uncertainty interval. Never use a scored-series lineup whose knownAt is after match start.

Ordered implementation

Phase 1. Establish roster truth and terminology

  1. Add series-level lineup evidence types and canonical builders.
  2. Group game rows by canonical series before deriving one lineup per team.
  3. Preserve evidence basis, source, effective time, and known time.
  4. Replace public "current starter" and "current substitute" claims with "last observed" labels.
  5. Retain latest observation and latest complete lineup separately.

Exit: no UI or artifact calls a lineup current without confirmation evidence.

Phase 2. Connect substitutes and roster eras

  1. Derive substitute participation by team, player, role, series count, and split game share.
  2. Feed derived substitute inputs into roster-era construction.
  3. Represent one-off and short substitutions as temporary states.
  4. Open a permanent era when the threshold or explicit source proves permanence.
  5. Move continuity updates from date boundaries to series boundaries.
  6. Bump checkpoint schema and inventory every new persisted map.

Exit: same-day lineup changes, returning starters, and permanent replacements replay identically in full and incremental builds.

Phase 3. Improve lineup-aware calculations

  1. Replace the complete-five-role cutoff with coverage-weighted role priors.
  2. Separate player-quality delta, coordination retention, and lineup uncertainty in the rating ledger.
  3. Add freshness decay for lineup evidence without treating elapsed time as a roster change.
  4. Add expected role mixtures for teams that rotate players.
  5. Require pregame-known evidence in exported walk-forward predictions.
  6. Record base evidence and realized movement for every roster-related channel.

Exit: four sourced roles contribute less than five but more than zero, and postgame roster knowledge cannot affect pregame evaluation.

Phase 4. Add reliability checks

  1. Generate provider disagreement reports for lineup, role, match identity, format, winner, and phase.
  2. Block promotion for unresolved recent disagreements in high-weight series.
  3. Add data-health metrics for complete roster sides, partial sides, stale lineup evidence, unresolved player IDs, and postgame-only lineups.
  4. Add roster-change, substitute, role-swap, partial-lineup, and unknown-lineup calibration slices.
  5. Require exact full-versus-incremental parity for roster-era state.

Exit: every published build has a machine-readable roster health report and paired accuracy result.

Phase 5. Improve the website

  1. Add a lineup card with observation date, source basis, completeness, freshness, and missing roles.
  2. Add a roster timeline for starters, temporary substitutes, role swaps, and permanent changes.
  3. Show team power, expected lineup adjustment, and uncertainty as separate values.
  4. Add a "what if this player starts?" control only after the calculation gates pass.
  5. Add a site-wide data-health panel with coverage end, retrieval time, source gaps, and model gate status.
  6. Link lineup claims to the source series or official announcement.

Exit: a user can tell what lineup was observed, how old it is, whether it is confirmed, and how it changes the rating.

Test plan

Unit tests

  • Partial roster merge preserves known roles.
  • Duplicate roles do not imply a current substitute.
  • Threshold edges at two and three series, and below and at 20% share.
  • Role swaps remain distinct from player replacements.
  • Expected lineup mixtures sum to one per role.
  • Evidence after match start is rejected for pregame use.

Replay tests

  • Two same-day series with different lineups.
  • Emergency substitute followed by returning starter.
  • Permanent replacement after repeated substitution.
  • Historical lineup correction.
  • Future lineup announcement does not change earlier predictions.
  • Checkpoint round-trip and incremental parity.

Corpus tests

  • Complete, partial, and missing lineup coverage by league.
  • Provider disagreement rate by competition tier.
  • Unresolved player identity count.
  • Lineup freshness distribution.
  • Known-before-start coverage for evaluated predictions.

UI tests

  • Observed lineups never render as confirmed without evidence.
  • Stale and partial states remain visible on mobile.
  • Source links identify the supporting series.
  • What-if changes announce updated probability and uncertainty.
  • Missing player data does not imply zero player strength.

Accuracy gates

Use paired walk-forward predictions clustered by canonical series. Compare against the currently published model on the same source corpus.

Release sequence

  1. Ship terminology and artifact schema changes without changing published ratings.
  2. Run the new calculations in shadow mode and retain both prediction exports.
  3. Gather enough substitute and roster-change series for stable slice estimates.
  4. Promote calculation changes only when every required accuracy and parity gate passes.
  5. Regenerate public artifacts into a new versioned generation while preserving the prior generation for rollback.
  6. Enable the what-if UI after the promoted artifacts expose lineup probabilities and provenance.

Risks and controls

Done criteria

  • No inferred lineup is labeled current or confirmed.
  • Every prediction records which lineup evidence was available before match start.
  • Temporary substitutes and permanent roster changes produce different state transitions.
  • Partial lineups contribute coverage-weighted player evidence.
  • Same-day series with different lineups replay correctly.
  • Roster state survives checkpoint round-trip and matches clean full replay.
  • Data-health output reports lineup coverage, age, identity gaps, and provider disagreements.
  • All static checks, tests, artifact validation, and incremental benchmarks pass.
  • The new calculation clears global, cross-region, league, roster-change, substitute, partial-lineup, and unknown-lineup gates.
  • Public artifact promotion remains blocked until every required gate passes.
