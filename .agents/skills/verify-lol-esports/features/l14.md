# L14: Loading and delivery

Use the owned static instance from the core procedure. Read L1–L8 and L13 for
the underlying ranking, detail, comparison, archive and tournament expectations.
Do not use a provider refresh or production mutation to measure performance.

1. Record the browser viewport, payload provenance and whether assets are cold or
   warm. Open Rankings, Regions, Matches, Tournaments, Legal, Privacy and Licenses
   at desktop and 390 px widths. Watch the first content, loading shells, status
   area and footer. Reserve space during loading; a healthy schedule must not
   briefly report stale data. Report lab layout shifts separately from field CLS.
2. Navigate through the four app views, change scope, and open team and region
   comparisons. The selected scope and addresses remain correct. Avoid successive
   full-screen and inner loading flashes. Close drawers and test Back and Forward.
   After loading Rankings, visit Tournaments and return to Rankings. The validated
   manifest must remain ready, with no manifest loading shell or new manifest request.
3. Open one team, then another. Load Players through its disclosure, reopen a
   team, and change scope. History and players must belong to that team and
   generation. The hidden board chart must not compete with an open detail.
4. Expand a match series, select an archive year, and paginate from the bottom.
   The next results stay at a stable height while loading and explicit pagination
   brings the result heading into view. A reload of an addressed page retains it.
5. With the local tournament fixture, delay a healthy health response during
   initial load and refresh. Keep the last valid status while pending. Then return
   an incomplete health response and a feed error: both must show truthful warnings
   while preserving usable content. Check one timer refresh, hidden-tab inactivity,
   return-to-tab refresh, and Swiss selections across an unchanged refresh.
6. Check a production bundle and its network dependencies. Legal pages should not
   load ranking data or chart code. Before opening a chart, Recharts must not be
   part of the initial module dependency graph. Team icons use small derivatives
   with bounded dimensions and bytes, and retain readable fallbacks.
7. Use local mock-bucket server tests to prove repeated HTML delivery reuses
   verified immutable work, active authority changes invalidate it, corrupt data
   cannot enter the cache, and legal routes do not read ranking storage. Never
   weaken provenance validation or change refresh cadence for a faster result.

Supporting checks include `tournamentBrowser.test.ts`, the ranking/address and
match prefetch browser tests, `railwayServer.test.ts`, `teamLogo.test.ts`,
`seoPrerender.test.ts`, and the production bundle check. Add regression cases to
the relevant existing suite when the behavior is missing. Run browser suites
serially with explicit timeouts and the resource controls in AGENTS.md.

Retain before/after measurements in the excluded run directory. Record observed
latency and layout separately from pass/fail correctness. Restore the default
scope and viewport, remove only owned fixture overrides, stop the exact owned
server, and confirm its listener closes.
