# L2: Scope filters and search

## Sub-features

Search, region, tier and tournament filters, season, sorting, pagination, and shared addresses.

## How to get to it (user POV)

Rankings at `/#rankings?scope=all`. The shell search has placeholder `Find a team`.

## Driving it with T3 preview

At mobile width, open the button whose name starts with `Filters` before using board controls or clearing search. Use `preview_type` on `input[placeholder="Find a team"]` with a team name from the board. Assert that the visible rows match it and the address contains its search. Save the address. Click `role=button[name="Clear search for T1"]` when the observed team is T1, or use the exact observed name. Assert that the full board returns. Navigate to the saved address, call `preview_evaluate` with `location.reload()`, and assert the same filtered rows and search input. Use the `Region` group and `All regions` button to reset region filters.

Use the same open tab at mobile and desktop widths for the address checks:

1. Open typed or linked Rankings hashes with region, team search, tournament,
   eligibility, sort, page size and page. Compare each board with a reload of
   that address. Back and Forward must restore the addressed board.
2. Reload `sort=rating` without `dir`. Power must remain highest first.
   A valid addressed page must remain selected after tournament options load.
3. Open and close a team detail. Keep the tournament filter. An exact tournament
   must include its unranked participants without changing the eligibility
   setting for the general board.
4. Follow the Rankings tab and the logo from a filtered board and from Matches.
   Both open the clean board for the selected scope, without the earlier
   filters or Matches page and page size.
5. Change a filter through its control. The address must match the board.
   Filter controls use `replaceState`, so these changes do not add history
   entries. Back and Forward apply to navigated addresses.

## Gotchas

Choose a team present in the loaded scope. If none exists, fail the search journey. Do not replace this with an empty-results proof.
