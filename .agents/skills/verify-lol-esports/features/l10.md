# L10: Automatic tournament ingestion

## Sub-features

Two-window ingestion, deduplication, discovery gates, and browser ledger.

## How to get to it (user POV)

Run the local ingestion tests. Generate a separate offline browser payload before opening Matches.

## Driving it with T3 preview and repository tests

Run the commands below through heavy-check on coding. Then drive L6 against the isolated generated payload and inspect its new event and preserved domestic history.

| ID | Public actions and expected result | Source / regression references | Reset |
| --- | --- | --- | --- |
| L10 | Run the local automatic tournament ingestion regression. A second date-window refresh preserves domestic history, deduplicates overlapping games, and retains the new event in global and year ledgers with series-atomic rating updates. Check gated audit discovery with an unchanged official probe, explicit opt-out and shadow defaults. Then exercise L6 with the offline fixture. | automaticTournamentIngestion and refreshOnce tests; captured Demacia Cup 2026 fixture; ranking-source-import and teamProfiles | Remove owned temporary data and restore the saved local public payload. |

For automatic tournament ingestion, run
`pnpm exec tsx --tsconfig tsconfig.app.json --test tests/automaticTournamentIngestion.test.ts tests/refreshOnce.test.ts`.
It runs the Railway refresh wrapper against a local Cargo fixture, checks baseline
preservation across two date windows, and checks both year and global ledgers.
The tests delete temporary inputs and keep computed ledgers in memory. They do
not leave a browser payload. The refresh tests also check discovery when the
official probe has no new match, explicit audit opt-out, shadow defaults, and success receipt requirements.
These tests use no provider or bucket credentials and make no production writes.
For L6, generate an isolated offline fixture from its captured games and domestic
evidence. Compare the ledger before and after home-league resolution, select the
event in both All seasons and its year, expand a series, and reload its deep link.
Label the fixture as offline verification, preserve source/model provenance, and
restore the saved local public payload after captures.

## Gotchas

Do not run `railway:refresh-once` against providers to verify this guide. Missing fixture publication means the browser half has not passed.

Use a disposable checkout with no existing `public/data` for the browser proof.
Run `pnpm install --frozen-lockfile`. Skip `pnpm data:pull` for this journey.
Generate both payloads from the retained fixture. The cup-only payload omits the
fixture's domestic home-league evidence. The second payload includes it.

```sh
export L10_PROOF_DIR="$(mktemp -d /tmp/lol-l10.XXXXXX)"
node --input-type=module <<'JS'
import { readFile, writeFile } from 'node:fs/promises'
const fixture = JSON.parse(await readFile('tests/fixtures/demaciaCup2026.json', 'utf8'))
for (const [name, matches] of [
  ['cup-only', fixture.matches],
  ['with-domestic', [...fixture.domesticEvidence, ...fixture.matches]],
]) {
  await writeFile(`${process.env.L10_PROOF_DIR}/${name}.json`, JSON.stringify({ ...fixture, matches }))
}
JS
for basis in cup-only with-domestic; do
  heavy-check -- pnpm exec tsx --tsconfig tsconfig.app.json scripts/build-static-snapshot.ts \
    --leaguepedia-json "$L10_PROOF_DIR/$basis.json" \
    --generated-at 2026-10-06T18:00:00.000Z \
    --output "$L10_PROOF_DIR/$basis.full.json" \
    --public-data-dir "$L10_PROOF_DIR/$basis/public/data"
done
mkdir -p public
test ! -e public/data
cp -R "$L10_PROOF_DIR/cup-only/public/data" public/data
env -u VITE_RANKING_DATA_URL pnpm dev --host 127.0.0.1 --port 43129 --strictPort
```

Outside hostname `coding`, omit the `heavy-check --` prefix. Record both source
manifests and their model/config identities. Label the proof as offline
verification of captured community inputs.

Open `/#matches?scope=all`. Select `2026 Demacia Cup Global Invitational` in the
Event select. The cup-only input has 27 raw event games, but missing domestic
evidence leaves
only one published series and one game. Capture that coverage gap. The full
payload must still expose all 15 event series and 27 games.
Keep this server running. From a second terminal in that same owned checkout,
replace only the owned browser payload. Copy real files so Vite sees added
archive pages through its public-file watcher:

```sh
mv public/data "$L10_PROOF_DIR/served-cup-only"
cp -R "$L10_PROOF_DIR/with-domestic/public/data" public/data
```

Run Doctor. Wait until the new match-page paths return JSON, because Vite
updates its public-file list asynchronously. The second page is
`/data/matches/pages/season-2026-2026000002.json`. If it still returns HTML after
a readiness retry, restart only the owned server. Then perform a full reload.
Require 15 event series and 27 games in All seasons and in the 2026 season.
Use the `Season` select when the archive has only one year. Compare the expanded
coverage and the added domestic history with the cup-only payload. Expand a
multi-game series and reload its address. Series expansion is local state and need not survive reload.
A captured reference snapshot with the event already present does not prove the
two-window ingestion checks above.

After captures, stop the exact server session and remove only the owned
fixture payload. Retain evidence outside the disposable checkout before
removing the checkout and its scratch fixture directory.
